# NH-7 Alert Delivery & Messaging Setup Guide

This guide walks you through setting up real-time multichannel alert delivery across **Telegram**, **Twilio SMS**, and **Twilio WhatsApp** for the NH-7 Landslide Early Warning System.

---

## 1. Quick Testing Mode: `DRY_RUN=true` (Default)

By default, the backend runs with `DRY_RUN=true`. In dry-run mode:
- No real network calls are made to external Telegram or Twilio servers.
- All alert dispatches and webhook responses are formatted and printed directly to standard output and backend logs.
- Safe for local testing, CI/CD pipelines, and judging demonstrations without consuming SMS credits or needing third-party API keys.

To enable live delivery, set `DRY_RUN=false` and configure the tokens below.

---

## 2. Telegram Bot Setup (Long Polling)

The Telegram bot uses **long polling** in a background worker thread. It requires **no public IP, domain, or webhook URL**, making it ideal for firewalled local environments and cloud deployments alike.

### Step 1: Create Your Bot with BotFather
1. Open Telegram and search for `@BotFather`.
2. Send the command:
   ```text
   /newbot
   ```
3. Follow the prompts to assign a display name (e.g. `NH-7 Landslide Early Warning`) and a unique username ending in `bot` (e.g. `nh7_landslide_warning_bot`).
4. Copy the HTTP API token generated by BotFather (looks like `7123456789:AAH...`).

### Step 2: Configure Environment Variables
Set the token in your `.env` or deployment environment:
```bash
TELEGRAM_BOT_TOKEN="7123456789:AAH..."
ENABLE_TELEGRAM_BOT="true"
DRY_RUN="false"
```

### Step 3: Supported Bot Commands
Users can message the bot directly with the following commands:
- `/start` - Displays welcome message and command cheat-sheet.
- `/status <segment>` - Checks live hazard risk for a sector with real weather (e.g. `/status Sirobagarh` or `/status seg_08`). Supports fuzzy matching.
- `/route <from> <to>` - Computes route-level landslide risk and travel advisories (e.g. `/route Rishikesh Joshimath`).
- `/subscribe <segment>` - Subscribes the Telegram `chat_id` to receive automated alerts when the sector enters High or Very High risk.
- `/unsubscribe` - Stops all automated alerts for the chat.
- `/lang en|hi` - Switches response language between English and Hindi.

## 3. Twilio SMS & WhatsApp Setup

Twilio delivers mission-critical SMS and WhatsApp notifications to highway travelers, local taxi unions, and emergency responders.

### Step 1: Obtain Twilio Credentials
1. Register or log in at [twilio.com](https://www.twilio.com).
2. On your Twilio Console dashboard, locate:
   - **Account SID**
   - **Auth Token**
   - **Twilio Phone Number** (or WhatsApp Sandbox number)

### Step 2: Configure Environment Variables
```bash
TWILIO_ACCOUNT_SID="ACXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX"
TWILIO_AUTH_TOKEN="your_auth_token_here"
TWILIO_FROM="+14155238886"  # Twilio phone number or WhatsApp sandbox sender
DRY_RUN="false"
```

### Step 3: Twilio WhatsApp Sandbox (Zero Cost Testing)
1. In the Twilio Console, navigate to **Messaging** > **Try it out** > **Send a WhatsApp message**.
2. Connect your personal device to the sandbox by sending the activation message (e.g. `join <sandbox-keyword>`) to `+1 415 523 8886`.
3. In `TWILIO_FROM`, specify `+14155238886` (the system automatically prepends `whatsapp:` when routing WhatsApp alerts).

### Step 4: Configure Inbound Webhook (`POST /webhook/sms`)
To allow travelers to query road conditions via two-way SMS or WhatsApp:
1. In Twilio Phone Numbers / Sandbox Settings, locate **A MESSAGE COMES IN**.
2. Set the webhook URL to:
   ```text
   https://<your-render-or-ngrok-domain>/webhook/sms
   ```
3. Set the HTTP method to `HTTP POST`.
4. Twilio forwards inbound messages to the API, which validates the `X-Twilio-Signature` and replies with compliant TwiML XML (capped at 320 characters).

### Supported SMS Commands
Travelers can text:
- `NH7 HELP` - Receives command instructions and emergency SDRF helpline numbers.
- `NH7 SEG08` (or `NH7 SIROBAGARH`) - Returns live risk tier, 3-day rainfall, and official closure status.
- `NH7 ROUTE RISHIKESH JOSHIMATH` - Returns maximum corridor risk, critical passes, and recommendation (`GO`, `CAUTION`, `AVOID`).

## 4. Periodic Alert Dispatcher & Cooldown Policy

The background scheduler checks all active subscriber sectors every **10 minutes**:
1. **Real Weather Only**: Calculates hazard tiers strictly using live Open-Meteo observations; never triggers alerts on simulated rainfall.
2. **Trigger Criteria**: Dispatches an alert only when a sector enters `High` or `Very High` hazard, or transitions to a different risk level compared to the previous dispatch.
3. **3-Hour Cooldown**: Prevents user fatigue by enforcing a minimum 3-hour cooldown window per user and segment before repeat notifications are issued.
4. **State Persistence**: Records all state transitions in `alert_state` and maintains a complete operational audit trail in `alert_log`.
